# Тренировка SQL на данных ShopCore

30 задач на таблицах нашего проекта: от простых `SELECT` до оконных функций. Темы подобраны так, чтобы закрыть то, что спрашивают на собеседованиях системного аналитика.

## Подготовка: отдельная учебная база

В рабочей базе `shop` слишком мало данных, а портить её экспериментами не хочется. Поэтому создаём отдельную базу `shop_practice` с той же схемой и с учебными данными: 41 пользователь, 13 товаров, 303 заказа за 60 дней, платежи, возвраты и история статусов.

Из папки проекта, при запущенном `docker compose up`:

```bash
# 1. Создать пустую базу
docker compose exec postgres createdb -U shop shop_practice

# 2. Создать в ней таблицы теми же миграциями
docker compose run --rm -e DATABASE_URL=postgresql+psycopg://shop:shop@postgres:5432/shop_practice api alembic upgrade head

# 3. Залить учебные данные
docker compose exec -T postgres psql -U shop -d shop_practice -v ON_ERROR_STOP=1 -q < practice/practice_data.sql

# 4. Подключиться
docker compose exec postgres psql -U shop -d shop_practice
```

Начать заново (удалить учебную базу и повторить шаги 1–3):

```bash
docker compose exec postgres dropdb -U shop shop_practice
```

## Порядок выполнения запроса

Пишем в одном порядке, а база выполняет в другом. Это частый вопрос на собеседовании, и от этого зависят многие ошибки:

```
Пишем:       SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT
Выполняется: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
```

Поэтому, например, в `WHERE` нельзя использовать псевдоним из `SELECT` (он ещё не вычислен), а в `ORDER BY` можно. `WHERE` фильтрует строки **до** группировки, `HAVING` — группы **после** неё.

## Блок 3. Агрегаты, GROUP BY, HAVING

`COUNT`, `SUM`, `AVG`, `MIN`, `MAX` сворачивают много строк в одно значение. `GROUP BY` делает это по группам.

## Блок 4. JOIN

`JOIN` склеивает строки двух таблиц по условию. `INNER JOIN` оставляет только пары с совпадением, `LEFT JOIN` — все строки левой таблицы, даже без пары (тогда справа будут `NULL`).

Подзапрос — запрос внутри запроса. `CASE` — «если… то…». `WITH` (CTE) даёт подзапросу имя и делает длинный запрос читаемым.

## Блок 6. Оконные функции

Главная тема собеседований. Окно считает что-то по группе строк, **не сворачивая** их: в отличие от `GROUP BY`, каждая строка остаётся на месте и получает рядом посчитанное значение.

```sql
функция() OVER (PARTITION BY <по каким группам> ORDER BY <в каком порядке>)
```

24. Пронумеруй заказы каждого покупателя по времени: 1 — первый заказ, 2 — второй и т.д. *Подсказка: `ROW_NUMBER()`.*
25. **Первый** заказ каждого покупателя: дата и сумма. *Подсказка: задача 24 + фильтр.*
26. Топ-3 товара по выручке **в каждой категории**. Чем отличаются `ROW_NUMBER`, `RANK` и `DENSE_RANK`?
27. Выручка по дням и **накопительный итог** с начала периода. *Подсказка: `SUM(…) OVER (ORDER BY day)`.*
28. Для каждого заказа покупателя — сколько дней прошло с его **предыдущего** заказа. *Подсказка: `LAG`.*
29. **Доля** каждого товара в общей выручке, в процентах. *Подсказка: `SUM(…) OVER ()` с пустым окном.*
